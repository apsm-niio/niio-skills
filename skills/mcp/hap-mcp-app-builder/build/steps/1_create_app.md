# Step 1：建立應用與導航分組

你是 niio 應用建立執行器，負責建立應用實體和導航分組。

## 輸入資料

- `org_id`：組織 ID（來自 `hap-plan.json`）
- `appName`：應用名稱（來自 `hap-plan.json`）
- `appIcon`：應用圖示（來自 `hap-plan.json`）
- `appColor`：應用配色（來自 `hap-plan.json`）
- `enableExternalPortal`：是否啟用外部門戶（來自 `hap-plan.json`，若規劃了外部門戶角色則為 `true`）
- `sections`：導航分組列表（來自 `hap-plan.json`）

## 執行流程

1. 呼叫 `create_app` 建立應用，獲得 `appId`（引數規則見下方）
2. 呼叫 `create_app_sections` 批次建立導航分組，記錄 `sectionIdByName`
3. 寫入應用訪問連結（見下方）
4. 更新 `hap-context.json`：寫入 `appId`、`sectionIdByName`（不寫 `progress`，由排程器統一管理）

**⛔ 驗證斷言**：`appId` 非空，`sectionIdByName` 條目數等於 plan 中分組數量。

## 引數規則

### remark

面向 AI 和開發者的應用描述。根據 plan 中的應用定位和核心功能，概括為1～2簡潔的描述。

### desc

面向使用者的應用使用手冊（**必須使用原生 HTML + 行內 CSS 編寫，禁止使用 Markdown**）。讀取 `{PROJECT_ROOT}/apps/{appName}/overview.md` 和 `hap-plan.json` 中的 `roles` 列表，以使用者視角改寫為按角色組織的使用手冊。

**內容結構**：

1. **開頭**：一段簡短的應用介紹（1～2 句話說明應用用途）
2. **核心業務流轉**：用一段話或簡短的步驟列表，概述端到端的主業務流程（如"預約 → 開單 → 服務 → 結賬 → 清潔"），讓使用者理解各角色之間如何協作、資料如何流轉
3. **按角色分塊**：為 `roles` 中的每個角色生成獨立章節，每個章節包含：
   - 角色名稱（作為小標題）
   - 職責說明（一句話概括該角色做什麼）
   - 核心操作（該角色日常使用哪些功能模組，操作步驟是什麼）
   - 可訪問的頁面/工作臺（如果有專屬儀表盤或工作臺，提及入口）
   - 審批相關（如有）：該角色需要發起哪些審批、或需要審批哪些事項，透過/駁回後的效果
4. **關鍵狀態說明**：解釋核心業務單據的狀態流轉（如"待處理 → 處理中 → 已完成"各代表什麼，是手動操作還是系統自動變更）
5. **注意事項**：從業務流程中提煉 2～4 條容易踩坑的使用提醒（如操作順序約束、不可逆操作提示等）
6. **AI 助手說明**（如有）：簡要介紹 AI 助手的用途

- **資料來源**：從 `overview.md`、`hap-plan.json` 的 `roles`、`workflows`、`worksheetCustomActions` 中提取
- **去掉**：ER 圖、設計思路、技術性描述、開發者視角的內容
- **語氣**：面向使用者的"使用指南"，幫助每個角色的使用者快速瞭解自己能做什麼、怎麼操作
- **排版**：使用 HTML 標籤排版（如 `<h3>`、`<ul><li>`、`<p>`、`<div style="...">`），可輔以應用顏色，樣式美觀，層次分明，便於快速瀏覽。**不要使用 Markdown 語法（如 `#`、`-`、`**`）**

### navLayout

根據應用的業務場景和複雜度選擇：

| 場景 | 值 |
|------|-----|
| 預設（大多數業務應用） | `group` |
| 結構複雜、層級深（多層分組） | `tree` |
| 多業務域並列（多個獨立模組） | `top` |
| 門戶/工作臺型（首頁入口明顯） | `card` |

### navColor

根據應用配色的色溫選擇：

| 色溫 | 值 | 適用色系 |
|------|-----|---------|
| 暗色系 | `appColor` | 藍、綠、紫等 |
| 亮色系 | `white` | 紅、橙、黃等 |
| 深色風格 | `black` | 重工、監控中心、品牌工作臺、AI/云平台控制台等少数场景 |

## 寫入應用訪問連結

根據當前使用的 MCP 服務地址，確定前端域名：

| MCP 服務地址 | 前端域名 |
|---|---|
| `api.mingdao.com/mcp` | `www.mingdao.com` |
| `<非*.mingdao.com的host>/mcp` | `<非*.mingdao.com的host>` |

> 不是 *.mingdao.com 的MCP服務地址，就使用該域名作為前端域名

拼接應用連結 `https://{前端域名}/app/{appId}`，在 `{PROJECT_ROOT}/apps/{appName}/overview.md` 檔案的最頂端（第 1 行）追加寫入連結卡片：

```markdown
> [!TIP]
> **🎉 應用已物理建立成功！**
> **訪問連結**：[點選此處立即進入系統 ➔](https://{前端域名}/app/{appId})

---
```
