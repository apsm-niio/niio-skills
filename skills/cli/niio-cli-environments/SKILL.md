# niio 多環境 / 多帳號操作守則

使用者可能同時授權了多個 niio 環境與帳號，每個都已登入儲存、各有一個名字（見 `hap auth accounts`）。
“在哪個環境、用哪個帳號執行”和命令本身一樣重要——選錯可能在不該動的環境上造成不可逆後果。

## 每次操作前

1. 先看現狀：`hap --json auth accounts`，讀出目前在用的是哪個（`active`），以及每個環境/帳號的名字、登入網址、帳號、組織。
2. 把使用者的措辭匹配到某個**環境/帳號**：優先按使用者說的名字；其次按登入網址/平台（niio SaaS、niio、使用者給的私有部署網域）與帳號匹配。匹配不唯一就走「停下來問」。
3. 切換：整段會話用 `hap auth use <名字>`；只此一條命令用 `hap --profile <名字> <命令>`。

## 什麼時候必須停下來問

- 使用者**沒指明用哪個環境/帳號**，且操作具破壞性（刪除應用/工作表/欄位/記錄、釋出、改角色權限、批次寫入）。
- 使用者的話能匹配到多個環境/帳號、或一個都匹配不上。

此時用問答卡片把候選環境/帳號列給使用者選，**不要擅自挑一個執行**，更不要預設用線上/正式的那個。

## 執行時

- 每次跑命令前，在回顯裡點明「目前環境 / 帳號 / 組織 / 登入網址」，讓使用者能一眼核對。
- 破壞性命令再加一句確認目前不是誤選的正式環境。

## 不該做

- 不要替使用者登入或登出（`auth login` / `auth logout`）——除非使用者明確要求。
- 不要把一個帳號的 token 跨環境/帳號複用——切換一律走 `auth use` / `--profile`，不手動搬運 token。

## 命令速查

```bash
hap auth accounts                 # 列出所有環境/帳號，目前的帶 *
hap --json auth accounts          # 同上，結構化輸出供程式判斷
hap auth use <名字>               # 切換目前使用的環境/帳號
hap --profile <名字> <命令>       # 只讓這一條命令臨時用某個環境/帳號
HAP_PROFILE=<名字> hap <命令>     # 僅這次命令使用指定的環境／帳號
hap auth whoami                   # 確認目前使用者 / 環境 / 組織
```

具體命令參數以 `hap auth <子命令> --help` 為準；要登入/登出或建應用、查資料等本身的操作，回到 `niio-cli` 及其指向的專門 skill。
