# niio 網站建置

對外使用 niio 與台灣繁體中文。先閱讀 [網站架構與部署](references/niio-as-database-guide.md)，依該文件建立前端及後端；需要確認 API 欄位語法時再讀 [API 參考](references/niio-api-usage-guide.md)。後者為協定參考，不能取代本部署驗證。

## 執行順序

1. **釐清網站資料範圍**：區分公開內容、會員資料、內部資料、寫入操作。隨附模板只提供公開內容的唯讀列表；會員／內部資料不得設為 public。這些需求需額外實作身分、租戶、資料列及操作權限，不能以「已有後端」當成已授權。
2. **透過可用 MCP 讀取結構**：探索當前連線提供的工具，以 `get_worksheet_structure` 等唯讀能力取得工作表、欄位與選項。依實際 schema 傳參，不硬編碼 MCP 工具前綴。AI 負責呼叫順序與參數。結構變更與新增示例資料只在已有使用者授權的範圍執行。
3. **分別確認網站、MCP、REST 設定**：MCP 成功不代表 REST 路由或驗證相容。不要從 MCP 網址推測 REST origin 或路徑，也不要自動把 MCP Token 轉用 REST。請部署管理者確認 REST 驗證模式及端點，秘密只放後端環境變數或秘密管理服務，不能貼進對話、提交到 git 或放入前端變數。
4. **先唯讀驗證**：確認 HTTPS origin、固定列表路徑、HTTP 狀態、JSON Content-Type、`success`、`data.rows`、欄位 ID、發布欄位的值與型別及篩選語法。禁止重新導向。404 HTML、401／403、格式不符或篩選失效時停止，回報已知證據，不猜替代路徑或跨網域重送憑證。記錄狀態與欄位結構，不記錄完整 Token 或客戶資料。
5. **建立後端白名單**：從 `assets/server.mjs.template` 與 `assets/server.config.mjs.template` 建立服務。每組公開內容指定固定路徑、發布條件、可公開欄位及排序。只有管理者確認可公開、已完成 REST 驗證的資料集才能啟用。不得提供接受任意 URL／工作表／filter／fields 的通用代理。
6. **建立前端**：依 `assets/config.js.template`、`assets/api.js.template`、`assets/main.js.template` 建立公開檔案。前端只呼叫同源 `/api/content/{資料集}`；只傳頁碼與每頁筆數。不要再使用舊版 `getRows(worksheetId, {filter, fields})` 或任意 rowId 詳情介面。
7. **驗收與部署**：先用模擬資料測試未發布列、不允許欄位、未知路由、寫入方法、偽造查詢、HTML／重新導向錯誤均受限制，再依授權完成本部署唯讀測試。只部署 public 目錄為靜態網站，後端秘密不得位於靜態根目錄。沒有後端能力時使用建置時產生的公開資料快照，不能退回瀏覽器直連含密鑰的 niio API。

## 完成回報

列出公開資料集與欄位、驗證過的部署／API 路徑、憑證保管位置（只列變數名稱）、測試結果、未完成項目、實際網址與修改範圍。模板通過離線測試不等於真實 niio 部署已相容。

只在需要表單／會員／內部功能時擴充後端，先說明必要的權限、輸入驗證、防濫用及錯誤處理。隨附唯讀模板本身不宣稱支援上述功能。
