# niio 前後端專案建置 Skill

## 簡介

這是一個專業的技能，用於使用niio niio（高階應用平台）作為資料庫建置獨立網站。提供完整的 niio + 前端專案建置指導。

## 適用場景

- ✅ 企業官網（產品展示、新聞資訊、案例展示）
- ✅ 內容管理網站（部落格、文件庫、知識庫）
- ✅ 資料展示平台（資料看板、報表展示）
- ✅ 表單收集系統（線上預約、問卷調查、詢價訂單）
- ✅ 營銷落地頁（活動頁面、促銷頁面）

## 核心能力

1. **niio 後臺設定**
   - 資料結構設計與建立
   - 示例資料填充（附件欄位必須填充圖片 URL）
   - API 憑證取得

2. **前端專案建置**
   - 專案結構設計
   - HTML/CSS/JS 程式碼編寫
   - 響應式設計

3. **API 整合**
   - niio API V3 封裝
   - 資料取得與渲染
   - 錯誤處理

4. **開發工作流**
   - 自動啟動本地開發伺服器
   - 完整的開發流程指導

## 工作流程

1. **需求理解與結構評估** - 讀取 niio 應用結構，評估是否滿足需求
2. **使用者確認** - 獲得使用者明確同意後再執行結構變更
3. **niio 後臺設定** - 建立/補充資料結構和示例資料
4. **取得 API 憑證** - 從 MCP 設定或 niio 後臺取得認證資訊
5. **前端專案建置** - 建立完整的專案結構和程式碼
6. **API 整合** - 實現前端與 niio API V3 的資料互動
7. **資料渲染** - 實現動態資料渲染和使用者互動
8. **啟動開發伺服器** - 自動啟動本地伺服器供預覽

## 核心原則

### 1. 資料來源原則（必須動態）
- ✅ 業務資料必須從 niio API 取得
- ❌ 禁止在程式碼中寫死業務資料

### 2. 只增不刪原則（紅線）
- ✅ 可以新增工作表、欄位、資料（需確認）
- ❌ 嚴禁刪除現有結構或資料

### 3. 使用者確認機制（強制）
- 🔴 任何結構變更必須徵得使用者明確同意
- 🔴 使用 `AskUserQuestion` 工具進行確認

### 4. 示例資料要求
- ✅ 每個新增工作表至少 5 條示例資料
- 🔴 附件欄位必須填充圖片 URL
- ⚠️ SingleSelect/MultipleSelect 篩選必須使用 key（UUID）

## 注意事項

1. **必須動態取得資料**: 業務資料必須從 niio API 取得，不能寫死在程式碼中
2. **使用者確認機制**: 任何結構變更必須徵得使用者明確同意
3. **只增不刪原則**: 絕不刪除現有工作表、欄位或資料
