# niio-skills 品牌移植交付結論

更新：2026-10-20。這是目前交付判準；其他註明日期的報告是各輪證據快照。

## 可交付到什麼程度

**可交付為「niio 品牌移植、文件及指定環境唯讀試用版」；不能宣稱「上游全部功能完全等價」或「所有 niio 部署功能已驗收」。**

移植所需的來源對應、繁中／品牌、必要技術名稱保留、固定版本、授權、安裝與技能可讀已有證據。目前未發現需停止此限定交付的 Skills 缺陷。後端、網站部署、角色與高副作用流程未驗收，不自動阻擋此交付，也不是使用者不懂部署造成的失敗。所有寫入、建置及正式啟用仍須依實際任務授權。

## 上游與 niio 的差異

對照固定上游 `71e0488b48ac06156249b62741fb16f0be4a1496` 與已安裝 niio 來源 `1d75354d251bf94d9dabf314f8f0c66b55d0e25c`，不是宣稱已同步上游最新版本。上游八技能 81 檔，niio 八技能 87 檔；按 hap- → niio- 路徑對應後無缺少的上游檔案，第三方授權逐位元組相符。檔案保留不代表行為完全相同。

|改動|性質與必要性|
|---|---|
|品牌名稱、繁中及台灣用語、技能／內部檔名／連結改為 niio|品牌移植必要。技術協定、套件及命令仍保留 HAP-Appkey、HAP-Sign、hap、hap-cli、mdye 等相容名稱。|
|移除預設指向上游雲端的假設；分開確認 niio MCP／REST／CLI；不挪用憑證|環境適用與安全指引必要。不同部署成功結果不能互相抵充。|
|hap-plan／hap-context 更名後的相容辨識、備份及衝突保護|既然採用新檔名，就需要避免舊專案遺失或重建；實際遷移不是一般新安裝的必要步驟。|
|安裝 receipt、回復續跑、檔案清單、固定來源生成與 CI|額外交付／維護工具，有本機或隔離測試；不是 niio 平台新增功能。|
|網站同源後端、公開欄位白名單|額外安全架構調整，超過純品牌替換。模板目前只供公開唯讀列表；不能把原通用前端直連能力視為完全保留。詳情、內部／會員資料及寫入需另案設計驗證，不恢復把密鑰放進前端的方式。|
|build_checkpoint.py、外掛預檢與欄位解析 helper、欄位 refresh／填值防護|額外本機穩定性改善；檢查點不會替後端證明防重複或完整遠端恢復。|
|工作流服務回應錯誤、平台品牌／網址設定、SDK／CLI 部署支援|平台或部署問題；不屬於翻譯規則可直接修正的範圍。|

比上游新增的六檔為：網站 server.mjs.template、server.config.mjs.template；外掛 view_project.py、field_values.mjs；builder build_checkpoint.py、project_files.py。沒有在此輪新增功能程式或改動正式安裝。

目前此範圍沒有仍需使用者安裝工具才能完成的 A 類工作。若後續發現翻譯、連結、固定來源或相容腳本的可重現缺陷，由 Skills 維護者修正。

## 真正會阻擋交付的條件

若出現缺少技能、錯誤協定／命令改名、密鑰進入前端或版本庫、來源／授權不可追溯、安裝破壞舊檔，屬 A 類，應停止受影響交付並由 Skills 維護者修正。目前沒有這些已知未結清缺陷。

若交付承諾改為「全部功能與上游等價」或「正式部署已完成」，網站模板的功能範圍差異、CLI／SDK 未實測及工作流入口未定位會阻擋該承諾；網站範圍差異由 Skills 維護者負責，部署支援由平台維護者負責，畫面結果由使用者在條件備妥後驗收。不能靠更名或重新分類將其說成通過。

現階段不要求使用者執行伺服器蒐集工具、不新增帳號、不部署網站、不重做已通過驗收；先依此限定範圍交付。需要某項功能時，再單獨準備其 B／C 條件。
