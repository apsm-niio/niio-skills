# 本機 MCP 套件驗收

2026-10-28，發布前實機驗收紀錄。正式交付方式為八個技能與每人自用的 stdio `niio_local_mcp`，NAS 與原 `/mcp` 切換已暫緩。

## 已完成

- 12 項組合安裝交易測試通過：首次安裝／回復、更新／回復／重裝同一版、其他設定保留、自訂技能與 MCP 區塊拒絕覆蓋、設定並行修改時自動回復、中斷續跑、手動設定明確接管、原本無設定檔的回復、服務與備份檔變更保護、服務載入失敗在切換前停止。
- 2 項 Windows 認證測試通過：合成憑證 CurrentUser DPAPI 加密→本機服務解密，以及新認證驗證失敗保留原檔。沒有把合成憑證當真實登入。
- 本機服務 21 項單元測試通過，涵蓋資料／工作流修正及認證／目的地限制；其中上游為模擬。
- 既有交付安裝 7 項與回復續跑 5 項測試通過，保留原技能專用入口。

- 產生與交付驗證通過：89 個產生檔案、八個根技能、十份 SKILL 文件、零品牌檢查問題；上游授權檔逐位元相符，八個安裝技能與來源一致。
- 完整 ZIP 使用者流程 13 項通過：在含中文與空白的隔離目錄解壓並離線安裝；未認證時不借用全域憑證；真實帳戶以 DPAPI 密文登入後列出 80 個工具；實際安裝服務在窄檢視讀回完整指定欄位；使用另一個完整新版 ZIP 更新並保留原認證；回復到可用舊版，再撤銷首次安裝；保留其他設定及技能；明確沿用本人既有認證可用；ZIP 不含本人的 PAT；實際 Codex 設定雜湊未改變。測試使用的加密認證檔已刪除。

完整流程的認證由維護驗收程序經私有管線提供給加密程序，沒有把 PAT 放進命令列、聊天或交付包。互動式隱藏輸入介面與失敗保留舊值另有程式測試；不把這次程序供值說成人工輸入實測。

## 證據界線

這些是 Windows／Node 24.19／Python 3.10 的證據，套件要求 Node 24 LTS 或更新版本。Node 22.12 在特定中文目錄載入 SDK 原生崩潰，同一 SDK 使用 Node 24.19 成功；沒有更動使用者的全域 Node。以上實機紀錄完成時尚未發布；發布時的 Ubuntu／Windows 離線 CI 結果請以對應提交的 GitHub Actions 為準，不將 CI 等同於 Linux 真實平台連線驗收。本版不包含 PAT、Codex 設定、測試證據或伺服器私鑰。

安裝器成功、SDK 獨立程序成功、Codex 既有對話實際載入是不同層級。每位新使用者仍需自己的平台權限，不能因套件驗收就宣稱第二真實身分、AppKey／OAuth 或上游所有功能通過。

## 伺服器清理

使用者授權移除的實際路徑為 `/opt/niio-mcp-production`、`/opt/niio-mcp-test`、`/opt/niio-two-issue-repair`；根目錄下的同名路徑不存在。11 個專用容器、7 個專用／未共用資料卷及 `niio-repair-vector-net` 已移除，18465–18468 測試埠已關閉。

原平台七個容器的 ID、啟動時間與狀態均保持，原 API 雜湊相同；未移除共用映像或平台網路。臨時 SSH 公鑰已精確撤銷，驗證新連線遭拒，本機公私鑰已刪除。原公開 `/mcp` 未切換，NAS 未修改。

完整清理收據留在本機維護證據目錄，沒有放入對外交付 ZIP。

## 發布整理補充

封存停用後，發布作業只執行離線單元測試及合成安裝交易，不重新啟用維護者的本機 MCP 或呼叫平台。另補上已停用設定在接管／更新時保留，以及 verify 不啟動停用服務的回歸測試。上方 13 項真實帳戶流程是封存前的證據，不宣稱發布後重新做過平台驗收。
