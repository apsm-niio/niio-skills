## 契約證據與限制

已取得同部署公開的 [OpenAPI YAML](https://niiodemo.apsm.com.tw/apidoc/application_v3/pat/en/openapi.yaml)，SHA-256 為 5afcc93b519a052a0ee638ce2bff4e1901fd82e5ff1e2737e575d217e680327a。

- 清單 viewId 非必填，fields 說明為要回傳的欄位，未交代第一個檢視的顯示欄位可把明確要求的其他欄位回成空值。
- 記錄更新 value 為 any；不代表每種欄位都接受所有 JSON 值，文件未交代數字轉換失敗會清空。
- 工作流 ValueRef 文件允許 literal 使用字串、數字、布林、陣列、物件或 null。這是通用值型別，不代表所有欄位接受相同形狀；仍足以要求欄位特定的轉換或明確拒絕，而非內部樹污染。
- 此 YAML 的 REST 更新使用 updateType，MCP 工具使用 type；因此不能憑同站文件就斷言 MCP 實際轉發到哪個 REST 路由。
- 文件未提供可驗證的部署版本；JSON 樹外觀可供定位線索，不能據此假造實作堆疊或程式行號。

## 可修改的範圍

此專案與已安裝來源是技能及其 Python 輔助程式，沒有目前部署中的 MCP／平台服務實作、主機管理入口或容器部署檔。公開同名舊專案也不能證明是現行服務，不以替換服務或修改無關程式冒充修復。

已直接修正本地可驗證的兩個誤擋問題：合法一般十進位字串、零檢視工作表。保留非法值拒絕與既有檢視的明確選用規則；這些不是遠端缺陷修復。後續遠端修復需要實際部署對應的服務原始碼／部署管道。目前維持未結案。

服務修正的驗收條件：
1. 明確 fields 與檢視投影語義一致；不可把未回傳值偽裝成真實空值。若設計要求檢視限制，須明確記錄與回覆。
2. 非法數字回明確錯誤，原值保留；合法數字／數字字串正常，明確清空另行測試。
3. 單選陣列正確正規化或在建立時明確拒絕；已污染草稿必須驗證失敗；多選陣列保持正確。
