# MCP 呼叫前校驗與相容路徑

此修正處理 Agent 使用技能時的三個已觀察風險，不包含遠端服務部署或修補。

| 風險 | 本次處理 | 保留界線 |
| --- | --- | --- |
| Number 接受非法字串後被清空 | builder 與 API 技能在送出前呼叫同一份本機校驗器，按當前 DSL 欄位型別拒絕無效值 | 繞過技能直接呼叫 MCP，仍未證明有相同防護 |
| 檢視顯示欄位之外的值在清單回空 | 已有檢視時，完整欄位讀回明確選用本任務獲准的檢視、欄位 ID，並比較同一筆資料的清單與詳情；無任何檢視時可省略 viewId | 沒有修補省略 viewId 的服務行為；不能把範圍較大的檢視當成自動後備 |
| 工作流單選常數陣列序列化污染 | 對已驗證的單選單值場景使用 key 字串；發布前檢查草稿中的內部 JSON 樹污染 | 不是全域陣列轉字串；記錄工具仍按 schema 使用選項陣列，多選與其他運算子須各自驗證 |

校驗器包含在兩個技能各自的 scripts/mcp_preflight.py，沒有額外套件依賴，不連線、不代送請求、不回顯欄位內容。兩份腳本由相同內容交付，覆寫來源與固定上游雜湊綁定；重新生成會保留它們。

`record` 模式校驗表歸屬、欄位 ID／alias、重複欄位、唯讀欄位、直接必填及有限數字；一般十進位數字字串也接受，不改寫原請求。此模式不宣稱覆蓋條件必填、公式、唯一值、跨表權限或所有平台規則。`list` 模式在表已有檢視時檢查顯式檢視，並檢查實體欄位及分頁參數；不保證檢視涵蓋完整欄位，仍須對照詳情。`snapshot` 模式偵測已知內部 JSON 樹污染；不取代平台校驗及工作流實際執行驗收。

2026-10-22 隔離對照已修正先前的過度限制：數字與一般數字字串均可寫入；沒有任何檢視的表可完整讀取；工作流多選陣列的建立與讀回正常，單選單元素陣列則仍污染且被平台誤判可發布。詳見 [契約調查結論](MCP_CONTRACT_FINDINGS.md)。本地校驗器的修正不能作為遠端服務 BUG 已修復的證據。

記錄寫入校驗成功後，Agent 必須送出同一份參數。若之後改動任何值，重新校驗；這是 Agent 執行程序，並不是平台強制的 middleware。

通過測試與實際資料讀回，才可宣稱對應使用路徑可用。未確認的 CLI、REST、SDK、一般成員權限及遠端錯誤輸入行為仍分開列未測或未結案。
