# 維護者最少資訊與後續人工驗收

這是集中待辦，不要求現在準備帳號。秘密僅提供受控本機來源／環境變數名稱，勿貼入 Issue／PR。

|---|---|---|---|

## 之後一次集中執行的人工清單

- [ ] 固定新版與舊版 SHA，確認來源乾淨；選擇安裝目錄，停止技能工作階段，執行更新並保存 receipt。
- [ ] 重開工作階段，確認八個頂層技能及 builder 的 plan/build 入口可載入；記錄實際路徑與讀取證據。
- [ ] 按 G1–G5 完成目標與工具版本核對；未備妥的列保持受阻，不採用預設環境。
- [ ] API 少量唯讀、四個 CLI 的既有環境／查詢、網站公開投影、檢視 SDK 唯讀，分別留下去敏紀錄，不能互相抵充。
- [ ] 由維護者按 G6 查歷史請求，不重新送觸發；將錯誤與按鈕成功歸到不同執行實例。
- [ ] 若需要舊檔遷移，按 G7 在副本驗證；原檔、鎖與備份保持完整。
- [ ] 在隔離安裝再演練一次 receipt 回復；正式回復前保存新增自訂變更。
- [ ] 一般成員／主管有效權限試用維持暫緩；另由可提供測試帳號的維護者安排。同仁的新使用者 MCP 唯讀驗收已完成，不再追加測試。

失敗立即保存完整去敏錯誤、時間窗／精度、工具參數與資料狀態。重試前先查是否已有副作用；不得用新建應用、重新發布、修改訂單或擴權來繞過驗收。

## 新使用者唯讀驗收

本清單供後續新使用者採用；2026-10-19 的同仁驗收已完成，不要求該同仁追加操作。已完成範圍見 [去敏摘要](NEW_USER_ACCEPTANCE_20261019.md)。一般成員／主管有效權限仍是另一項驗收。

1. 保存固定 commit、安裝 receipt，按技能名稱配對來源及安裝目錄；使用 `scripts/verify_install.py` 逐技能比較 SHA-256。若有缺檔、多檔或變更先保留差異，不直接覆蓋。
2. 使用 `python scripts/onboarding_inventory.py <固定版本checkout>` 產生 JSON 清單；以 `skills[技能名稱]` 的 `source`、`fileCount`、`sha256` 建表，禁止將名稱與數字分別排序後配對。工具只查來源，不能替代 receipt／安裝副本核對。
3. 重開後確認八個技能名稱及根 SKILL.md 可讀；依 [安裝文件](INSTALL.md#新使用者技能安裝後另做-mcp-授權) 完成本機個人 PAT 授權。記錄客戶端版本及授權方式，不記密鑰。
4. 唯讀列出可存取應用，請使用者選定目標。從該應用的工作表清單確認名稱、ID 與歸屬，再讀結構；不要只從瀏覽器網址猜 worksheetId。
5. 使用已獲准的少量欄位，最多讀取 3 筆；本清單的上限僅適用此 MCP 新使用者抽查。G1–G5 的其他通道仍依各自上限執行。記錄結果與筆數，不保存業務值、記錄 ID 或完整回應。
6. 分開記錄安裝、技能可讀、MCP 連線、工作表結構與資料抽查。八技能安裝通過不等於八技能全部遠端功能通過。失敗保留去敏錯誤，不以寫入、擴權或觸發工作流排查。

`onboarding_inventory.py` 另列交付目錄內 PowerShell 檔案的「非 ASCII 且無 UTF-8 BOM」風險，發現風險時退出碼為 1；這是保守編碼檢查，不執行腳本，也不代替 Windows PowerShell 5.1 Parser API 驗證。
