# 維護者最少資訊與後續人工驗收

這是集中待辦，不要求現在準備帳號。秘密僅提供受控本機來源／環境變數名稱，勿貼入 Issue／PR。

|編號|最少資料|阻擋技能|取得後的驗收|
|---|---|---|---|
|G1|該部署 REST 版本、完整唯讀 method/URL、請求與回應 schema、Filter、認證模式；適用憑證的受控來源|API、網站、外掛 REST 擴充|依 acceptance 包對合成表讀 1 筆，核對 HTTP／Content-Type／業務成功／欄位形狀；不推測 MCP 對應路徑|
|G2|應用／表／檢視 ID、准許讀取的欄位與穩定合成資料基準、發布欄位值型別及可公開範圍|所有資料通道|鎖定 target、最多 1 筆；網站須確認草稿與秘密欄位不外露|
|G3|相容 hap-cli 的固定版本、既有執行環境路徑、停用自動更新的方法（若有）、既有 profile 對應部署／組織／應用；不需要提供 token 值|四個 CLI|核對本機 help、既有 accounts/whoami 與少量 list；app-editor 僅 inspect／schema，不改資料或發布|
|G4|既有網站 origin、同源後端代理位置、非秘密 server.config、REST 已驗證證據|網站|唯讀 GET 已啟用資料集；檢查瀏覽器資源與回應無密鑰，資料僅發布列／白名單欄位|
|G5|平台開發面板完整初始化命令、mdye/SDK 支援版本、既有專案路徑與鎖檔、非秘密 mdye.json、既有檢視入口及開發權限|檢視外掛|先 preflight；在既有檢視執行 readOne，核對 SDK 目標、1 筆資料、實際瀏覽器畫面與錯誤；發布另行授權|
|G6|先前 trigger 的 request/correlation ID、入口接收紀錄、下游 HTTP status/Content-Type/body、執行實例 ID 與部署版本；保留時區與時間精度|builder 自動觸發流程的部署診斷|依既有 niio-trigger-audit 時窗串接接收→下游→執行實例，與後來按鈕成功入口比較；不重觸發|
|G7|已允許 hardlink/symlink 的受控驗證環境或管理者提供拒絕原因（非要求本機提權）|builder 舊檔遷移 Windows 真實連結驗證|在副本執行原 test_project_files.py，核對原始位元組備份、冪等性與 symlink 拒絕；不更改保護策略|

沒有在目前工作區找到可用的部署端原始碼／伺服器日誌；不能從客戶端錯誤判斷請求未接收、未執行或下游未產生副作用。既有按鈕入口成功也不證明 MCP 觸發入口成功。

## 之後一次集中執行的人工清單

- [ ] 固定新版與舊版 SHA，確認來源乾淨；選擇安裝目錄，停止技能工作階段，執行更新並保存 receipt。
- [ ] 重開工作階段，確認八個頂層技能及 builder 的 plan/build 入口可載入；記錄實際路徑與讀取證據。
- [ ] 按 G1–G5 完成目標與工具版本核對；未備妥的列保持受阻，不採用預設環境。
- [ ] API 少量唯讀、四個 CLI 的既有環境／查詢、網站公開投影、檢視 SDK 唯讀，分別留下去敏紀錄，不能互相抵充。
- [ ] 由維護者按 G6 查歷史請求，不重新送觸發；將錯誤與按鈕成功歸到不同執行實例。
- [ ] 若需要舊檔遷移，按 G7 在副本驗證；原檔、鎖與備份保持完整。
- [ ] 在隔離安裝再演練一次 receipt 回復；正式回復前保存新增自訂變更。
- [ ] 角色、同仁帳號及權限試用維持暫緩；另有授權與準備完成後才排入。

失敗立即保存完整去敏錯誤、時間窗／精度、工具參數與資料狀態。重試前先查是否已有副作用；不得用新建應用、重新發布、修改訂單或擴權來繞過驗收。
